**ТЗ: Android-приложение “Snus Cooldown”**

---

## 1. Цель

Контроль приёма: разрешено **2 раза в сутки** — в 09:00 и 21:00.
В остальное время действие заблокировано.

---

## 2. Платформа и стек

* Android Studio
* Язык: Kotlin
* Архитектура: MVVM
* Хранение: DataStore (или Room при расширении)
* Минимум SDK: 26+

---

## 3. Основной функционал

### 3.1 Главный экран

Элементы:

* Кнопка **Submit**
* Таймер (обратный отсчёт до следующего окна)
* Текст статуса:

    * “Можно принять”
    * “Следующее окно в HH:MM:SS”

---

### 3.2 Логика времени

**Фиксированные окна:**

* 09:00–09:59
* 21:00–21:59

**Правила:**

* Внутри окна → кнопка активна (если ещё не использована)
* После нажатия:

    * сохраняется факт приёма (timestamp)
    * кнопка становится disabled до следующего окна
* Вне окна → кнопка disabled

---

### 3.3 Таймер

* Обновление каждую секунду
* Плавная анимация (CountDownTimer или coroutine ticker)
* Показывает время до ближайшего:

    * 09:00 или 21:00

---

## 4. Анти-чит защита (важно)

### 4.1 Изменение времени вручную

* Сохранять:

    * `lastSubmitTimestamp`
    * `lastKnownSystemTime`
* При запуске:

    * если текущее время < сохранённого → **блокировать кнопку** (подозрение на откат времени)

---

### 4.2 Перезапуск приложения

* Всё состояние хранится локально (DataStore)
* Нельзя “сбросить” кулдаун перезапуском

---

### 4.3 Удаление данных

* Минимум:

    * хранить флаг “первый запуск”
* Опционально (усиление):

    * использовать `SharedPreferences + backup=false`
    * или привязка к Android ID (не идеально, но усложняет)

---

### 4.4 Использование в рамках окна

* Внутри окна разрешён **только 1 submit**
* Проверка:

    * если timestamp уже в текущем окне → блок

---

### 4.5 Пересечение суток

* Логика не по “дням”, а по окнам времени
* Не важно, когда был последний запуск

---

## 5. Логика определения следующего окна

Псевдокод:

```
now = текущее время

if now < 09:00 → next = 09:00
if 09:00 <= now < 21:00 → next = 21:00
if now >= 21:00 → next = завтра 09:00
```

---

## 6. UX детали

* Кнопка:

    * Enabled → зелёная
    * Disabled → серая
* После нажатия:

    * краткая анимация (scale/fade)
* Таймер:

    * формат HH:MM:SS
* Без уведомлений (по требованию)

---

## 7. Структура данных

```
lastSubmitTimestamp: Long
lastKnownSystemTime: Long
```

Опционально:

```
lastSubmitWindow: ENUM (MORNING / EVENING)
```

---

## 8. Edge cases

* Приложение открыто во время переключения окна (08:59 → 09:00)

    * таймер должен пересчитать состояние
* Пользователь не открыл приложение весь день

    * ничего не ломается
* Часовой пояс сменился

    * ориентироваться на локальное время устройства

---

## 9. Расширения (необязательно)

* История приёмов
* Статистика (дни без пропусков)
* Виджет на экран

---

## 10. Критерии готовности

* Нельзя нажать кнопку вне окна
* Нельзя нажать 2 раза в одном окне
* Нельзя обойти через смену времени
* Таймер корректно считает до следующего окна
* Состояние сохраняется после перезапуска
